# 05 — Forbidden Patterns

> If you catch yourself doing any of these, **stop and restart** using the
> allowlisted tool. "Just this once" is how invented tools creep in.

## 1. Invented Tools & APIs

| ❌ Forbidden | ✅ Do instead |
|-------------|---------------|
| Guessing a component/prop/token (`<Button variant="fancy">`) | Run `astryx component Button` / read shadcn docs page |
| Inventing a CLI command/flag (`astryx generate button`) | Run `<cli> --help` / `manifest --json` |
| Inventing an npm package (`@my/button-kit`) | Use Astryx/shadcn registry |
| Inventing a file path (`components/FancyButton.tsx`) | `npx shadcn@latest add …` or Astryx import |

## 2. Hand-Rolled Replacements

| ❌ Forbidden | ✅ Do instead |
|-------------|---------------|
| Custom `Button`, `Dialog`, `Modal`, `Toast`, `Tooltip`, `Tabs`, `Table`, `Input`, `Select`, `Form` from scratch | Astryx component or shadcn `add` |
| Hand-rolled focus trap / modal / dropdown logic | Astryx/shadcn component + MWG Popover/dialog guide |
| Hand-rolled form state + validation | Astryx/shadcn form + MWG `:user-invalid` |
| Hand-rolled animation library | MWG View Transitions / `@starting-style` / scroll-driven animations |
| Hand-rolled tooltip positioning | MWG Anchor Positioning guide |

## 3. New Libraries & Polyfills

| ❌ Forbidden | ✅ Do instead |
|-------------|---------------|
| `npm i @mui/*`, `chakra`, `antd`, `bootstrap`, `mantine`, `headlessui`… | Astryx or shadcn (per [04](04-decision-tree.md)) |
| Polyfill for a natively supported feature | MWG guide + lightweight fallback |
| Animation lib (framer-motion, GSAP) for a CSS-able transition | MWG animation guides |
| Date/form/chart lib duplicating Astryx/shadcn | Check `astryx search` / `shadcn search` first |

## 4. Mixing Systems

| ❌ Forbidden | ✅ Do instead |
|-------------|---------------|
| Astryx + shadcn components on the same screen | Pick one per [04](04-decision-tree.md) |
| shadcn components in an Astryx project (or vice versa) without approval | Ask the user; declare the exception |
| Two themes / two CSS systems fighting | One theme: Astryx tokens **or** shadcn CSS vars |

## 5. Skipping Verification

| ❌ Forbidden | ✅ Do instead |
|-------------|---------------|
| Writing UI code from memory | Run discovery CLI first, cite output |
| Copying code from blogs/Stack Overflow | Use CLI/docs/registry output |
| Ignoring `legacy-scan` findings | Fix flagged legacy patterns |
| Skipping a11y (unlabeled inputs, missing alt, keyboard traps) | MWG accessibility guidance |

## 6. Silent Workarounds

| ❌ Forbidden | ✅ Do instead |
|-------------|---------------|
| "The tool doesn't have it, so I'll build a quick custom one" | Stop, show empty search results, ask user |
| Installing a package to "fill a gap" without approval | Ask user; add via [07](07-how-to-add-a-rule.md) if approved |
| Forking Astryx/shadcn source to restyle | Theme tokens / CSS vars / `className` / swizzle |

## 7. Signatures, Attributions & Trailers

| ❌ Forbidden | ✅ Do instead |
|-------------|---------------|
| `Co-Authored-By: …` in commit messages | Clean commit message only — subject + optional body, no trailers |
| AI labels / bot tags in code, comments, or PR descriptions | Write as if directly by a human developer |
| `Generated by …` / `Written by AI` headers in files | No headers — just the code |
| Signatures in docs, READMEs, or responses | Clean output only |

> **Rule:** output only clean code, commit messages, and descriptions.
> If a tool/hook tries to append a trailer automatically, remove it before
> committing (e.g. amend the message). Never ship a trailer.

---

**Self-test before finishing:** search your diff for any import that is not
(a) Astryx, (b) shadcn-owned code, (c) the project's existing deps, or
(d) a native platform API. If you find one, remove it or get approval.
Also search the diff for `Co-Authored-By`, `Generated by`, or any AI/bot tag —
if you find one, remove it.
